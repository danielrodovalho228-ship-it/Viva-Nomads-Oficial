- **Evidência (código, `main`):**
  - `src/app/(dashboard)/dashboard/propostas/[id]/page.tsx:15-16`: `const p = await lerProposta(id); if (!p) notFound();`.
  - `src/lib/data/propostas-actions.ts:841`: `const { data: pRow } = await s.supabase.from("propostas")…maybeSingle();`. O **`error` é descartado**: se a consulta falhar, `p` vem `null` e a tela mostra 404 em vez da tela de erro.
- **Contraprova:** a outra candidata da busca, `admin/parceiros/pedidos/[id]/page.tsx:22-32`, já trata o erro ("Achado 42": `if (falha) throw …`). Não é defeito.
- **Por que a auditoria do #3667 não pegou:** ela procurou `if (!data) notFound()` na **página**, mas aqui a consulta mora num helper (`lerProposta`) que engole o erro.
- **Correção sugerida:** `lerProposta` lança quando houver `error` (ou devolve um estado de erro distinto de `null`), igual ao #3667.
- **Spec de guarda:** estender o `e-erros-consulta-nao-e-404.test.ts` para os helpers de leitura usados por páginas com `notFound()`: o helper não pode desestruturar só `data` de uma consulta cujo `null` vira `notFound()`.
